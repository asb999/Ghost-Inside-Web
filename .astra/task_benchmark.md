# 任务书：对标《双人成行》《双影奇境》的拆解分析与优化规划（10/17 Demo Day + 赛季路线）

## 一、背景（规划者必读）

本仓库已有：
- `game/web/` —— 10/5 线上提交版 MVP（Vite + Three.js，七节拍：生活切片→完美花园→赞许收集者→饭桌裂缝→正确答案污染→表态点→我不知道结尾），17 项机器自检 harness 在 `.astra/harness/`。规划前请通读 `game/web/src/` 全部源码与 `game/data/cases/case_001_optimal_life.json`，**先弄清已实现什么、机制隐喻是什么**，再提优化——不要规划已存在的东西。
- `.astra/PLAN.md` / `.astra/DECISIONS.md` —— MVP 施工契约与 16 条已锁定决策（含对标初判：一节拍一机制即隐喻；双人合作不在 MVP）。
- `_gdd_import.md`（GDD v1.2，与飞书主文档同步）—— 四条张力线 × 五幕节拍的关系架构。
- `.workbuddy/memory/MEMORY.md` —— 项目长期决策。

## 二、对标对象与要提炼的内容

对标《双人成行》（It Takes Two）与《双影奇境》（Split Fiction），提炼四个维度：
1. **设计哲学**：机制即隐喻（每个机制必须表达关系/主题）、「一关一机制玩完即弃」的新鲜度节奏、机制教学三段式（安全引入→变奏→组合考试）如何落到单人叙事游戏
2. **关卡与场景**：场景奇观与叙事功能如何绑定、失败-重试的节奏（不惩罚）、检查点设计
3. **合作设计的单人转译**：双人成行的「双方能力互补」如何转译为「玩家 × Ghost」的不对称协作（Ghost 是 AI 伙伴，工具渐暖弧线已锁定）；评估哪些关卡段落值得改为「玩家做 A、Ghost 提供 B 能力」的协作解谜
4. **叙事与玩法的咬合**：他们的剧情服务于机制切换，我们的机制服务于心理命题——找出互相借鉴的边界，避免丢掉已验证的「表态点/转化/污染」三大原生机制

## 三、产出要求

产出一份可直接执行的优化规划（八段契约），分三个优先级层：
- **P0 · 10/17 前可落地**：不推翻 MVP 架构，只增强（如：花园机制变奏、收集者战的第二阶段、Ghost 协作交互点）。每项给出工作量估计与验收方式
- **P1 · Demo Day 差异化**：评委记忆点（如 Ghost 双人合作演示模式、岔路回廊的机制变奏）
- **P2 · 赛季路线**：与 GDD「未来场景与赛道规划」衔接

每条建议必须标注：借鉴来源（哪个游戏的哪个具体设计）→ 转译方式 → 对应我们哪个已有节拍/系统 → 机器可验收的判定标准（harness 可扩展项）或人工走查项。

## 四、边界与红线

- 不得破坏 MVP 已锁定的：三条红线、表态点四档、转化胜利、正确答案污染、Ghost 工具渐暖、记忆人物不可对话
- 不引入联网多人/账号/引擎迁移（仍 Three.js → Godot）
- P0 建议不得使 10/5 MVP 交付物失效（harness 必须保持可扩展而非重写）
