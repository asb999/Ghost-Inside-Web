# Ghost Inside 《留一个位置》Greybox

## 目标

基于当前 `game/web` Three.js 项目，实现一个 5–7 分钟可从头到尾玩通的 Greybox，只验证：

> 跑酷 → 承担 → 变重 → 第一次跳不过 → 三段记忆重新分配责任 → 发现自己的调动通知 → 保留而非丢弃 → 再跳同一断层并成功。

不做正式美术，使用 Cube / Plane / Capsule 和已有素材。

## 冻结设计

- 林澈是成年男性，长期是家中最懂事、最可靠的人，拿到外地调动/工作机会。
- 家庭同时有母亲健康事务、父亲线上事务和弟弟申请选择。家人爱他但习惯依赖他，没有人明说“你不能走”。
- 不使用“最优人生系统”，不新增世界观，不把家人写成反派。
- 操作只保留 WASD/方向移动、Space 跳跃、E 拿起/放下/互动；Shift 仅已有时保留。
- 不做 ABC、心理测试、拼句、证据面板、长报告、正误评分、accept/revise/hold、大段阅读。

## 四个物品

- 母亲药盒：`Carried → Shared`，放入家庭共同提醒区，不是扔还母亲。
- 父亲手机：`Carried → Returned`，交还后玩家只做一次提示，父亲自己完成最后一步。
- 弟弟申请表：`Carried → Returned`，还给弟弟让他自己先想。
- 林澈调动通知：`Hidden → Revealed → Kept`，尝试丢弃时会回到玩家，只能放入 `KEEP / 自己的位置`。
- 物品数据至少含 `id/type/owner/weight/currentState/validTargets`。

## 负重

- 0/1/2/3 件责任的跑速：100%/97%/93%/88%。
- 0/1/2/3 件责任的跳跃：100%/96%/90%/80–82%。
- 跳跃差异明显，移动只轻微变慢。获得物品后至少有玩家身上的物件、视觉连接和更重落地声反馈。

## 状态流程

`INTRO → TUTORIAL → COLLECT_RESPONSIBILITIES → FIRST_JUMP_FAIL → MEMORY_HUB → PUZZLE_MEDICINE / PUZZLE_PHONE / PUZZLE_APPLICATION → RESPONSIBILITIES_RESOLVED → SECOND_JUMP_FAIL → TRANSFER_NOTICE_REVEAL → TRANSFER_NOTICE_KEPT → FINAL_RUN → FINAL_JUMP → ENDING`

1. 温暖的家庭餐厅/客厅，先拿碗、水果、水，学会 E。
2. 依次获得父亲手机、母亲药盒、弟弟申请表，三件都留在玩家身上。
3. 同一断层空载稳定可过，满载必定跳不过。失败不死，约 1 秒回起跳点；第二次显示过去的空载林澈通过残影。
4. 失败后打开三个路径清晰、顺序自由的短记忆区，通过上述物品操作重新分配三份责任。
5. 三责任解除后移动/跳跃恢复，第二次跳同一断层仍差一点，提示还带着某样东西。
6. 揭示之前被其他责任遮住的调动通知。丢弃会被拒绝，放入自己的位置后变为 `Kept`。
7. 第三次使用恢复后参数通过完全相同的断层，必须有明显落地、镜头、音效、音乐释放和环境打开反馈。
8. 弟弟问该选哪个，林澈删除“我觉得你应该…”，发送“你自己比较想去哪？”。调动通知亮起，不替他决定，向前行走后 Fade Out。

## 实现约束

- 先检查并复用现有 Player Controller、Jump、E Interaction、Checkpoint、Subtitle、Audio 和 3D Scene，不无必要重写。
- 失败不死亡；物品不永久丢失；连续失败有容错；心理意义优先由移动、跳跃、拿起、携带、放下和环境变化表达。
- 不新增 Boss、战斗、AI NPC、多结局、技能、成长、收集、复杂 UI、大地图、新世界观、最优人生系统、心理评分、诊断报告。
- 不触碰用户现有 2.5D 未提交修改。

## 机器验收

1. 构建成功，无 console/page/resource error；正式输入可从开始到 `ENDING/closed`，不直写状态。
2. 四物品迁移严格；三责任不能跳过谜题直接解除；调动通知不能丢弃。
3. 负重数 0/1/2/3 与指定移动/跳跃比例对应，解除后恢复。
4. 断层几何不变：满载第一次必失败；三责任解除但通知未 `Kept` 时第二次必失败；通知 `Kept` 后第三次通过。
5. 失败不死亡并回起跳点；物品不丢失；零输入不自动推进。
6. 不渲染旧表态点、证据芯片、accept/revise/hold、最优人生系统、Boss 或长表格。
7. 自动截图至少覆盖：初始家庭、三件负重、第一次断层、一个记忆谜题、调动通知反转、最终跳跃成功。
8. harness 退出 0，至少一条 `[PASS]`，无 `[FAIL]`。

## 结尾可理解性修复

- 最终跳跃落地后必须出现可见的“弟弟的消息”互动点，并明确提示按 E。
- 玩家必须实际互动并发送“你自己比较想去哪？”，出口才开放。
- 未回复前不能直接走到结尾；回复后道路或出口要明显亮起。
- 到达出口后显示明确的“第一关完成”画面，不能只停在场景里。

## 游戏入口、重新开始与首批 3D 素材

- 第一关之前增加独立的整体游戏开始页，使用用户提供的主视觉；开始游戏后再进入《留一个位置》的章节页。
- 第一关完成页增加“重新开始”，完整清空关卡状态并回到整体开始页。
- 使用 Tripo 官方 v3 API，从用户参考图生成一个低面数、带纹理的 Ghost 3D 模型；API Key 只存在于本次进程，不写入仓库。
- Three.js 优先加载生成的 GLB；模型加载失败时保留现有几何占位，不影响游玩。
- 验收覆盖：整体开始页 → 章节页 → 完整通关 → 完成页 → 重新开始 → 状态完全复位；GLB 请求成功且无资源错误。

## 正式 3D 角色与关键物件（V0.3）

- 本关可操控角色固定为过去的林澈；心灵调理师以附身方式介入，不额外显示第二名玩家角色。
- 以 `Assets/Character/林澈.png` 为人物身份依据，生成不改身份、服装与配色的标准 A-pose，再制作可绑骨的正式 3D 角色。
- 最少具备待机、移动、起跳、下落、落地、互动六类动作；动作资源失败时仍能以备用角色完整通关。
- 责任物件与教学物件不再共用方块：碗、水杯、水果、手机、药盒、申请书、调动通知、家庭提醒区、父亲与弟弟的归还点、丢弃装置、自己的位置、弟弟消息均须有可辨认轮廓。
- 家庭、走廊、三段记忆、断层与出口须形成不同的空间气氛，但不改变冻结玩法与关卡路径。
- 角色与场景需控制复杂度，保持浏览器流畅；所有外部 3D 资源必须有本地副本与加载失败备用方案。
- 验收覆盖：正式角色显示、动作状态切换、携带物跟随、所有关键物件可辨认、完整通关、重新开始、第二次进入、角色资源被阻断时仍可玩。

## 全身动作与责任跑酷（V0.4）

- 林澈的程序动作必须驱动腿、膝、脚、骨盆、脊柱、上臂与前臂，禁止只摆手、模型平移。
- 在剧情大断层前设置三段连续小断层和一个横向移动障碍；小断层或障碍失败只快速回到路线起点，不改变剧情阶段、不丢失物品。
- 玩家必须以满负重、卸下三份责任、保留自己的通知三种状态穿越同一路线，再分别尝试同一个剧情大断层。
- 关卡操作时长增加约 45–60 秒，但不增加新按键、新系统、战斗、收集或额外剧情文本。
- 教学物品互动后必须真实出现在餐桌上，提供最基本的空间反馈。
- 验收覆盖：腿部骨骼实际参与动作、三段小断层、移动障碍、小断层快速重生、跑酷路线至少三次穿越、原剧情闭环与重新开始。

## 林澈朝向与自然步态修复（V0.5）

- 只修改角色朝向和移动动作，不改关卡、剧情、跑酷参数与美术模型。
- W/A/S/D 四个方向移动时，角色正面必须朝向实际世界位移方向；180 度转身必须走最短角度并平滑过渡。
- 跑步循环由实际移动速度驱动，不允许原地计时造成脚步与位移脱节。
- 步态必须区分支撑腿与摆动腿，包含髋部重心、膝盖屈伸、脚掌抬落、脊柱反向扭转和手臂自然摆动。
- 起步、停止和急转向需要短暂混合，不能从静止姿势瞬间跳到最大摆幅。
- 验收覆盖：四方向朝向误差、180 度转身、腿部与手臂反相、左右脚交替支撑、停止回正，以及完整关卡回归。

## 肢体可读性、加载占位与同伴比例修复（V0.6）

- 只处理林澈步态的前臂/小腿可读性、正式模型加载前的占位显示、Ghost 与林澈的视觉比例，不改玩法与关卡参数。
- 跑动时肘关节必须保持自然弯曲并随前后摆臂变化；膝关节必须在摆动腿回收时明显弯曲、支撑腿着地时接近伸直。
- 正式角色加载过程中不显示胶囊人；只有模型明确加载失败时才启用备用角色。
- Ghost 的最长尺寸从接近成人身高降低为林澈身高约 55%–60%，保持伴随精灵而非第二名成人角色的观感。
- 验收覆盖：半步周期前后的小腿和前臂角度变化、加载中占位隐藏、加载失败备用角色可用、Ghost/林澈比例，以及完整关卡回归。
