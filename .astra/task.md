# Ghost Inside 3D 切片 Demo：可玩性与视觉打磨

## 目标

在现有 `game/web` Three.js 3D Demo 上完成一轮有限工时、高收益优化，把当前约 6 分钟流程压缩成 4–5 分钟的展示型垂直切片。重点让玩家操作真实影响进程，并接入 `New Assets_20261004_01.png` 中可用的场景视觉。

## 已确认范围

- 保留现有主流程：生活切片 → 完美花园 → 赞许收集者 → 饭桌裂缝 → 正确答案污染 → 表态点 → 尾声 → 结案。
- 不新增岔路回廊、清理幕、最优解 BOSS、第二章内容。
- 不做 Tripo/复杂 3D 模型、存档、账号、移动端适配、真实 LLM 网关。
- 展示型 Demo 优先：失败应有反馈，但不能长时间卡关；连续失败应有 Ghost 辅助或窗口放宽。
- 只用 `←/→`、`空格`、`E` 完整通关；不依赖 `↑/↓` 或 W/S。
- 总体验目标 4–5 分钟，允许机器时间推进测试；人工体验另行确认。

## 必做改动

### 1. 完美花园调优

- 掌声加速从 9.6 降到约 8.6。
- 放宽弹幕墙时间窗口，确保约 20fps 的内嵌浏览器仍容易读懂和通过。
- 不增加路线长度或新机制。

### 2. 赞许收集者：从等待改为主动生存

- 将三轮压缩为两轮，整体时长明显缩短。
- 只使用左右移动、跳跃、E；移除对前后移动的需求。
- 修正竞技场、怪物、玩家、弹幕围绕不同中心的问题。
- 每轮必须通过玩家实际躲避或站入明确安全区才会削减防御；零输入不能自动通关。
- 弹幕必须有清楚预告、安全缺口与轮次反馈。
- 受击必须有可观察后果：短暂停顿、闪烁、震动、进度损失或短轮重试，不能只记日志。
- 连续失败后自动扩大安全窗口或触发 Ghost 辅助，避免展示卡死。
- 防御归零后仍保留靠近按 E“转化”，不改成击杀。

### 3. 正确答案污染：从纯等待改为主动抵抗

- 现有五个污染事件仍保留，数据与叙事顺序不变。
- 每个关键阶段出现短暂 `E` 抵抗窗口；玩家至少完成一次真实抵抗，才可进入表态。
- 抵抗能延缓或短暂守住选项，但不能永久阻止污染；最后由玩家主动按 E 撕开表态入口。
- 有清晰倒计时、操作提示与成功/错过反馈。
- 该段总时长从约 30 秒压缩到约 12–18 秒。

### 4. 视觉素材接入

- 裁切 `New Assets_20261004_01.png` 中 1a/1b/1c/1d/1e/3a 六个场景区域，移除标签和白边。
- 新图是低分辨率 RGB 合成图，仅作为远景、叙事卡背景或短转场；不从 2a/2b/3b 棋盘格区域抠透明角色。
- 开始、花园、收集者、饭桌、污染、尾声呈现冷蓝→暗红→暖黄→褪色→落雪白的视觉节奏。
- 维持文字可读性与纯色回退；资源失败不能黑屏。
- 可优先复用仓库内已有高分辨率 `title_art.png`、`white_corridor_bg.png`、`archive_room_bg.png` 与透明角色立绘，但新合成图至少要在竞技场、污染、尾声中实际出现。

### 5. 流程压缩

- 收集者两轮化。
- 饭桌不新增交互，压缩重复文案或停留；47 条揭示保留。
- 污染压缩到 12–18 秒。
- 开场、表态、尾声核心叙事与安全边界不变。

## 不可破坏约束

- `white_corridor.json` 与其哈希基线不修改。
- 现有证据、表态校验、离线/超时/非法响应回退和秘密边界不削弱。
- AI/provider 不得改变世界状态或案例数据。
- 所有外部资源缺失时仍可完整走到 `closed`。
- 不使用破坏性 Git 操作，不覆盖用户无关修改。

## 验收意图

- 构建成功，首页与必需资源返回成功，无 console/page error。
- 完整流程仍能到 `closed`，七个节拍顺序、47 条揭示、五个污染事件、三档合法表态均保留。
- 完整通关只使用 left/right/jump/interact。
- 收集者零输入不能自动降低全部防御；正确操作可在两轮内归零；受击有可观察后果；辅助机制可避免永久卡关。
- 玩家和弹幕始终处于可见竞技场范围，生成中心与怪物一致。
- 污染阶段至少记录一次正式抵抗事件，最后一次主动交互后才进入表态；正常速度总长 12–18 秒。
- 六张场景裁切资源存在并能被构建；新图至少在收集者、污染、尾声显示。
- 现有安全、断网、性能、交付物检查保持通过；相关旧检查按两轮战斗与新污染输入更新。
- 最终自检命令输出至少一条 `[PASS]`、无 `[FAIL]` 且退出码 0。
