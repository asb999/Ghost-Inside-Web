## lark-cli 踩坑记录（重要，复用）

1. **App Secret 必须走 stdin 写入 keychain**：直接写 `.env` 后 `auth login` 会报 `The client secret is invalid.`
   正解：`printf '%s' "<secret>" | lark-cli config init --force-init --app-id <id> --app-secret-stdin`
   （配置落 `C:\Users\Kamijo\.lark-cli\hermes\config.json`，Windows 上 secret 不明文存盘）
   验证凭据有效性：curl `https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal`
2. **设备授权流程**：`auth login --recommend --no-wait --json` 拿 `verification_url` + `device_code`（**600s 过期**）
   → 用户浏览器授权 → 再 `auth login --device-code <code>`（可阻塞最长 10 分钟，需 timeout ≥600s）
   每次重启授权会作废上一轮 device code。
3. **必须先读内置 skill 再写文档**：`lark-cli skills read lark-doc references/lark-doc-create.md`（还有 `lark-doc-md.md`）
4. **`@file` 只接受 cwd 相对路径**，传绝对路径报 `unsafe file path` → 先 `cd` 到目标目录
5. **踩过的格式坑**：同一 markdown 表格行内出现 ≥2 处 `**加粗**` 会被飞书解析器错位配对
   （例：`| **父亲**（50 岁） | 制造冲突（**非反派**） |` 渲染成 `**父亲**（50 岁）**`）
   规避：每行只保留一处加粗，或改用文字表述（本例改为「定位为非反派」）
6. **bot 身份创建文档**会尝试自动给当前 CLI 用户授 full_access；未登录时 `permission_grant.status = skipped`
   → 用户能打开的最稳做法：登录后用 `--as user --parent-position my_library` 重建
